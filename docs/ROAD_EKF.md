# Дорожная модель: пересмотр концепции

Вход Python по умолчанию — `road_ekf`. Это новый экспериментальный движок. Старый `road_particle_filter` остаётся явно выбираемым вариантом для сравнения и регрессионных тестов. Swift-движок iOS ещё не перенесён на эту архитектуру.

## Что изменилось

Положение живёт на направленном графе: дискретная гипотеза содержит ребро, допустимого преемника и историю переходов. Её EKF оценивает `[s, v, b_a, psi, b_w]`: расстояние по ребру, скорость, смещение акселерометра, курс и смещение гироскопа. Координаты вычисляются из геометрии ребра. Состояния свободных координат E/N в основном фильтре нет.

Гироскоп предсказывает курс, акселерометр — изменение скорости. Ограничение дороги имеет вид `wrap(psi − theta(s)) = 0`. Его якобиан `[-dtheta/ds, 0, 0, 1, 0]` связывает положение с курсом на изгибе. Благодаря перекрёстной ковариации поворот может исправить расстояние, скорость и смещения, а не только прижать нарисованную точку к дороге. На прямой `dtheta/ds = 0`: модель не получает вымышленного измерения пройденного расстояния.

Перед перекрёстком гипотеза делится между разрешёнными преемниками с равным априорным весом. Затем гироскоп/ограничение дороги обновляет веса. Здесь нет повторного использования гироскопа одновременно в выборе преемника и его likelihood. Учитываются направления движения и turn restrictions.

При переходе границ рёбер распределение расстояния делится с помощью усечённых нормальных распределений. Переносятся полные совместные моменты, включая корреляции скорости и смещений. На длинных рёбрах распределение делится на ячейки по 60 м. Слияние учитывает как внутренние ковариации, так и различия средних. Банк ограничен 64 гипотезами; потеря массы при сокращении явно диагностируется. Это приближение, а не точный байесовский posterior.

Основная линия — текущая наиболее весомая гипотеза этого банка. Экспорт и карта соединяют точки геометрией известных рёбер. При смене несовместимых гипотез линия разрывается: найденный впоследствии вариант не выдаётся за непрерывно измеренный маршрут. `DisplayRouteWalker`, независимый EKF и эвристика парковки не подменяют эту линию. Свободный EKF остаётся только диагностическим baseline.

## Малые полигоны и их смысл

По умолчанию каждый полигон — буфер **6 м в каждую сторону** вокруг участка дороги длиной **не более 60 м**. Его максимальная площадь — около 833 м², с учётом округлённых концов. Показывается не больше пяти гипотез на один момент времени; совокупная площадь не превышает примерно 4166 м². Радиус не растёт со временем без GPS. Кругов вокруг свободного EKF в новом движке нет.

Размер коридора — ограничение отображения. Вероятностное содержимое не подгоняется под размер: интегрируется масса, действительно находящаяся в выбранном коротком окне. `represented_mass` — доля условного распределения сохранённого банка, попавшая в показанные окна. Она может быть значительно меньше 0.95. Это не вероятность правильности маршрута; отсутствующий в банке истинный путь этим числом не учитывается.

- `CONCENTRATED`: одна показанная гипотеза содержит не менее 0.8 условной массы, без большой недавней потери массы при сокращении банка. Это характеристика модели, не гарантия точности.
- `AMBIGUOUS`: есть несколько вариантов либо отображённая локальная гипотеза недостаточно определена.
- `LOST`: нет поддерживаемой дорожной оценки. Полигона и текущей позиции нет.

Пропуск IMU прерывает дорожную оценку до следующего принятого GPS. Если исходный GPS дальше 60 м от графа, обычный режим ждёт пригодных видимых фиксов прогрева. В режиме `gps_start_only` это явная ошибка инициализации. Выход за граф не заменяется большим кругом или произвольным snap.

## GPS и обработка IMU

GPS применяется в своё время: IMU-шаг разбивается на моменты фиксов. Для 10 Гц информация GPS ограничивается эквивалентом примерно одного независимого измерения в секунду; коэффициент шума распространяется на положение, скорость и курс. В начальном приоре один и тот же GPS не учитывается дважды.

Без явно записанной калибровки прогрева начальный курс не читается из будущих фиксов. При известной оси крепления используется продольное ускорение в раме автомобиля. Поле `reference_locations` не читается новым координатором вообще; эталон используется только при вычислении метрик и построении зелёной линии отчёта.

Линейный якобиан обрезания скорости у нуля ошибочно стирает поддержку продолжающегося движения. Поэтому рядом с границами скорости среднее и ковариация предсказания вычисляются положительной кубатурой распределения; в обычном диапазоне используется аналитический якобиан. Это смешанный Gaussian-filter predictor с EKF-обновлением, а не утверждение о точности линеаризации на границе.

Удар по акселерометру больше не выключает гироскоп. Каналы проверяются независимо; длительное подавление курса после вертикального толчка в новом движке отсутствует. На реальной записи в первом повороте это прежнее правило удаляло около 25° измеренного изменения курса.

Флаги старого ZUPT, ограничения частоты ZUPT и accel deadband не управляют новым фильтром. Скорость и смещения оценивает EKF. Общая предварительная обработка IMU, включая явно включённые `leveling_recovery_tau_s` и `accel_smooth_window_s`, пока сохраняется. Центрированные окна означают офлайн-обработку с просмотром будущей IMU; нулевая задержка не заявляется. По умолчанию обе экспериментальные коррекции выключены.

## Ограничения и проверка

Граф не создаёт измерение скорости на длинной прямой. При нескольких дорогах с одинаковой последовательностью поворотов и отсутствии внешнего измерения расстояния маршрут может остаться неоднозначным. Сужение коридора этого не устраняет. Реальная траектория автомобиля также может отличаться от осевой линии OSM: ширина 6 м — допущение для прототипа, а не дорожная разметка из карты.

Тесты `test_road_ekf.py` проверяют сохранение совместных моментов при разбиении распределения, отсутствие фиктивной информации о расстоянии на прямой, коррекцию расстояния на изгибе, перенос через короткие рёбра, отсутствие полигонов при потере IMU, ограничения геометрии, выбор ветки по гироскопу и неизменность результата после подмены спрятанного GPS. Метрики учитывают LOST как промах покрытия; ошибка позиции вычисляется только для доступных оценок, рядом указывается availability.

Повторение реальных проверок на уже импортированных записях:

```sh
processor/.venv/bin/python tools/road_ekf_benchmark.py \
  --trips runs/review-20min/2026-07-22/trip runs/review-20min/2026-07-26/trip \
  --graph runs/review-map.graphml --output runs/road-ekf-validation
```

Обычный запуск:

```sh
processor/.venv/bin/geotrace reconstruct --trip PATH --graph cache/spb.graphml \
  --algorithm road-ekf --radius 30000
processor/.venv/bin/geotrace report --run PATH
```

Размер графа должен покрывать допустимый маршрут от стартовой позиции; graph extent нельзя выбирать по спрятанному эталону.

## Основание для архитектуры

Разделение дискретной дорожной гипотезы и условного непрерывного фильтра использовано, например, в [Moore et al., 2021, Tracking Multiple Vehicles Constrained to a Road Network](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2021.744185/full). В той работе другие измерения — визуальные наблюдения с UAV. Она поддерживает структурный выбор модели, но не доказывает точность восстановления по нашему IMU. Формулы дорожного EKF и усечения реализованы здесь отдельно; код статьи не копировался.
