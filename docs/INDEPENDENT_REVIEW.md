# Независимое ревью GPS-route-recovery

Дата: 2026-09-08. Проверялся текущий Python working tree, включая незакоммиченные правки из брифа. Исходные пользовательские изменения и записи поездок сохранены; коммит и публикация не выполнялись.

## Статус

**Архитектура пересмотрена после этого аудита:** новый основной движок — дорожный `road_ekf`, описанный в [ROAD_EKF.md](ROAD_EKF.md). Таблица ниже документирует исправления и ограничения прежнего движка. Его EKF-круги и DisplayRouteWalker не используются новой моделью.

Это воспроизводимый **экспериментальный офлайн-прототип**, а не система с гарантией восстановления единственного маршрута. Ниже перечислены исправленные программные и математические ошибки; это не утверждение об отсутствии остальных ошибок. Реальные испытания не позволяют обещать ни точный маршрут при многоминутном отсутствии GPS, ни калиброванное покрытие 95%.

Порог ускорения не восстанавливает ненаблюдаемую скорость: он подавляет одновременно смещение датчика и настоящее плавное ускорение/торможение. Тихая IMU и согласие с собственной оценкой скорости не доказывают остановку. Граф помогает различать гипотезы, но отсутствующая дорога и потерянная при resampling гипотеза не восстанавливаются автоматически.

## Исправленные ошибки

|---|---|---|

При отсутствии калибровки остаётся явно менее надёжный мировой вектор. |
| Якобиан EKF | Не учитывал зависимость `a_E cos(psi)+a_N sin(psi)` от `psi` | Добавлена производная `-a_E sin(psi)+a_N cos(psi)`; проверяется конечными разностями всей функции перехода. Для измерения в раме автомобиля эта производная равна нулю. |
| Интегрирование ограниченной скорости | Скорость обрезалась после вычисления перемещения; тормозящая машина могла сместиться назад | Перемещение — интеграл ограниченной скорости, с учётом момента остановки и достижения `max_speed`. Якобиан согласован с этим интегралом. |
| Ковариация | Hard reanchor уменьшал дисперсию курса, оставляя старые перекрёстные ковариации, что могло нарушить положительную определённость | Сбрасываются строки/столбцы переустанавливаемых скорости и курса. |
| Шум EKF | Изменение частоты фильтра меняло накопленную дисперсию за одинаковое физическое время | Белые шумы заданы как непрерывные плотности; интегрированная дисперсия масштабируется временем. Численные значения всё ещё требуют измерительной калибровки. |
| Пропуски IMU | `gap_exceeded` вычислялся, но координатор игнорировал его, поскольку у ресемплированного шага маленький `dt` | В недостоверных интервалах не интегрируется отсутствующее измерение; неопределённость увеличивается, ZUPT запрещён. |
| Удары | Подстановка нулевого сырого сигнала всё равно интегрировала отрицательное смещение датчика | Режим `coast` обнуляет именно управляющее ускорение и поворот; шум/неопределённость остаются. |
| Короткие рёбра | Остаток перемещения обрезался до длины первого следующего ребра | Остаток переносится через несколько рёбер; регрессия проверяет цепочку двухметровых сегментов. |
| Шум положения частиц | `max(ds,0)` превращал симметричный шум в положительный дрейф даже на стоянке | Шум остаётся знаковым; кинематическое перемещение вычисляется отдельно. |
| Дорожные веса | Во время outage обновление весов по гироскопу/дороге выключалось | Обновление работает и без GPS, с масштабом по физическому времени, независимо от частоты GPS и вывода отчёта. |
| Importance sampling | Выбор ветки уже учитывал гироскоп, затем тот же фактор повторно входил в вес | Добавлена поправка `p(edge)/q(edge)` для направляемого гироскопом proposal. Принудительное притягивание курса к выбранной ветке по умолчанию выключено. |
| Численная устойчивость | Произведение малых likelihood обнулялось и возвращало равномерные веса | Накопление весов в логарифмах с вычитанием максимума; очень плохой GPS сохраняет диагностику divergence. |
| Независимый baseline | Дорожный consensus изменял EKF, называвшийся независимым инерциальным baseline | Обратное влияние карты на baseline отключено. |
| Отображаемая линия | Walker не позволял ехать медленнее последней GPS-скорости; также переопределял период выходных отсчётов | Удалён постоянный нижний предел скорости; отдельная переменная времени walker. Его положение и дорожный posterior измеряются отдельно. |
| Тихое состояние / ZUPT | Начало тихого интервала помечалось задним числом; начальные biases могли измеряться на ровном движении | Требуется уже прошедшее тихое окно. Начальные biases и обычный ZUPT требуют наблюдённой малой GPS-скорости. `zupt_requires_gps=False` остаётся экспериментальным. |
| Кватернионы | Разрыв знака `q ↔ -q` искажает производную ориентации | Перед дифференцированием выбирается непрерывный знак. Дубли времён удаляются; ненормированный кватернион обрабатывается одинаково в оценке yaw и вращении вектора. |
| Ресемплирование | Внешние отсчёты попадали в крайние bins; последний шаг выходил за конец записи; на каждый bin сканировалась вся IMU | Реальная обрезка окна, точный последний `dt`, поиск границ в отсортированном массиве. |
| GPS recovery | Разностная скорость GPS сравнивалась с Doppler-скоростью без учёта погрешности положения, особенно плохо при 10 Гц | Порог учитывает шум разности двух позиций и `dt`; курс по двум позициям проверяется только при достаточном перемещении. Физическая достижимость ограничена скоростью и при уже достигнутом лимите. |
| Полигональная масса | Мелкие компоненты отбрасывались после выбора 95% массы | Выбранная масса не отбрасывается из-за порога отображения; упрощение сохраняет исходную область, границы считаются покрытыми. |
| Метрики | Круг EKF считался правильно выбранной веткой; большие интервалы без GPS линейно заполнялись «истиной» | Branch-метрики используют дорожные компоненты; интерполяция эталона не пересекает разрывы >2 секунд; площадь оценивается на тех же временных отсчётах, что и покрытие. |
| Значение «95%» | Круги имели жёсткий предел 2 км и почти не зависели от выбранной confidence; confidence региона выдавалась за confidence маршрута | Используется двумерная chi-square-квантиль и наибольшая собственная дисперсия, без искусственного потолка. Калибровка явно отсутствует; вероятность точного маршрута не заявляется. |
| Артефакты | GeoJSON называл withheld GPS синтетически испорченным; report мог показывать новый трек со старыми метриками | Исправлено происхождение GPS во всех экспортах; report пересчитывает метрики для того же трека, который рисует. |
| Парковка | В начало завершающего окна передавалась скорость конца поездки; отрицательный GPS residual трактовался как задний ход | Используется скорость начала окна; направление не выводится из остатка позиции. Для старых сохранённых синтетических записей оставлен совместимый путь мирового вектора. |

### Что такое `display_route.py`

`DisplayRouteWalker` — эвристика непрерывной линии для карты. Он выбирает преемника на перекрёстке и не возвращается к отвергнутой ветке до переинициализации. Гладкость линии не является свидетельством правильности маршрута. Этот модуль не меняет состояния EKF/PF, но раньше именно его координаты выдавались под именем `road_particle_filter` без отдельной оценки самого posterior.

В явно выбранном legacy-режиме `road_particle_filter` эта линия сохраняется для сравнения. В новом основном `road_ekf` walker полностью исключён из оценки и отображения. В результатах добавлены `baseline-road-posterior.geojson`, отдельные ошибки `baselines.road_posterior`, дорожные регионы `road-posterior-uncertainty.geojson` и `polygons.road_posterior`. В отчёте есть отключаемый слой дорожного posterior. `branches.top1_accuracy` означает покрытие эталона наиболее вероятным **связным коридором**; это не точность определения названия улицы или OSM-ребра. Интерпретация записывается рядом с числом.

## Проверки

Автоматические проверки включают исходный набор тестов и независимые регрессии: конечные разности якобиана, ограничение скорости, положительную определённость ковариации после reanchor, сохранение расстояния на коротких рёбрах, отсутствие дрейфа от знакового шума, importance correction, полную комбинацию новых флагов, независимость от частоты вывода, подмену withheld GPS до и после импорта, согласованность gyro/quaternion.

Команда:

```sh
processor/.venv/bin/python -m pytest processor/tests -q
```

Итог и таблицы реальных прогонов заполняются после завершения контрольных запусков ниже.

## Протокол реальных данных

1. Одинаковый split для всех вариантов: GPS виден 120 секунд после начала движения плюс стояночный pre-roll; последующие фиксы только для оценки.
2. Предварительное сравнение: 22–26 июля, 600 секунд, 500 частиц, seed 42, `default`, `smooth5-db2`, `combined`.
3. `combined`: smooth=5, deadband=2, leveling=20, vibration=0.02g, minimum ZUPT interval=5 секунд, GPS requirement=false. Это проверка конкретной комбинации, не всего пространства настроек.
4. 22–25 июля — session 0. Для 26 июля session 0 начинается в 31.38°E за пределами имеющейся карты; использована session 1. Исключение основано на покрытии начальной GPS-точки картой, не на полученной ошибке.
5. Более длительный контроль: 22 июля/session 0 и 26 июля/session 1, 1200 секунд, 5000 частиц, seed 42, default и smooth5-db2. Для него объединены существующие `spb.graphml` и `spb-parkgolovo.graphml`; эталон не использовался для выбора или вырезания дорог.
6. Скрипт сохраняет конфигурации, использованные поездки, метрики, диагностику и хеш исходников/карты. Импорт проходит запись и повторную загрузку того же trip-формата, что используется CLI.
7. При оценке отдельно отмечаются разрывы/неправдоподобные скачки GPS и покрытие эталона графом. Скрытый настоящий GPS сам по себе не является безошибочной истиной. Эти проверки выполняются **после** реконструкции и не корректируют её.

Повторение короткого сравнения:

```sh
processor/.venv/bin/python tools/review_benchmark.py \
  --sessions 2026-07-26:1 --output runs/review-repeat --reports
```

Повторение длинного сравнения с сохранённой объединённой картой:

```sh
processor/.venv/bin/python tools/review_benchmark.py \
  --days 2026-07-22 2026-07-26 --sessions 2026-07-26:1 \
  --duration 1200 --particles 5000 --variants default smooth5-db2 \
  --graph runs/review-map.graphml --output runs/review-20min-repeat --reports
```

Короткие прогоны сохраняют промежуточную ревизию: после их запуска были дополнительно исправлены coast при ударах, диагностика качества эталона и некоторые экспорты. Длинные прогоны включают эти изменения. Хеши позволяют различать версии. Сравнивать числа из разных ревизий и разных карт как чистый эффект одного флага нельзя.

## Ограничения, которые остаются

- **Наблюдаемость и качество датчиков.** Гироскоп плюс начальная ориентация позволяют считать движение, но ошибки tilt и bias интегрируются. AHRS, использующий акселерометр для выравнивания, смешивает наклон и ускорение; `leveling_recovery` не является точным обратным фильтром. Для длительной точности нужны дополнительные независимые ограничения: например, скорость колёс/OBD, достоверные остановки или внешние ориентиры.
- **Неполная карта и ненадёжный эталон.** На нескольких днях значительная доля эталонных точек удалена от графа. Это может означать отсутствующие дороги, плохой GPS или оба фактора. На таких отрезках невозможность road-only модели должна учитываться отдельно от качества IMU.
- **Вероятности не калиброваны.** Исправление численной математики не оценивает реальные спектры шумов, их корреляции и вероятность отсутствия истинной гипотезы в конечном наборе частиц. Частоты успешного покрытия надо проверять на новых поездках, считая независимыми поездки/окна, а не тысячи соседних секунд.
- **Нет сертификации единственного маршрута.** Particle depletion, неоднозначные повороты и неверное постоянное крепление могут оставить уверенную, но неправильную гипотезу. Walker дополнительно фиксирует уже выбранный поворот. Для оценки целого пути нужен отдельный MAP/fixed-lag smoother или хранение родословной гипотез, а не только независимые координаты во времени.
- **Офлайн-обработка.** Центрированные Hampel/boxcar окна и начальная калибровка по прогреву используют будущие относительно отдельного отсчёта IMU-данные. Это не утечка скрытого GPS, но это не потоковый алгоритм с нулевой задержкой. Нужны отдельные причинные фильтры/явная задержка для on-device режима.
- **Парковочный модуль остаётся эвристическим.** Его signed-speed динамика, ковариация и score не заменяют полноценный фильтр парковки. Завершение файла логгера не доказывает факт парковки. Недостаточно подтверждённый кандидат больше не подменяет финальную дорожную позицию.
- **Swift/iOS.** Исправлен и проверяется Python processor. Численная эквивалентность Swift-реализации после этих правок не заявляется; перенос и отдельные fixture parity tests остаются отдельной задачей.
- Старые сохранённые конфигурации с `heading_snap_gain>0` сохраняют эту явно эвристическую настройку. Новый default — 0. Сохранённые старые reports/metrics не переписывались массово.

## Научная основа и границы заимствования

- Oliver J. Woodman, *An introduction to inertial navigation*, Cambridge, 2007: [технический отчёт](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-696.html), [PDF](https://www.cl.cam.ac.uk/techreports/UCAM-CL-TR-696.pdf). Использован для проверки природы интегрируемых ошибок ориентации/IMU; приведённые там ошибки конкретного устройства не переносились на этот логгер.
- CMU 10-708, *Monte Carlo and Sequential Monte Carlo Methods*: [лекция](https://www.cs.cmu.edu/~epxing/Class/10708-19/notes/lecture-13/). Importance weight должен учитывать отношение целевой плотности и proposal. Код поправки выведен для существующей модели, внешний исходный код не копировался.
- Sebastian Thrun, *Particle Filters in Robotics*: [авторская страница публикации](https://www.cs.cmu.edu/~thrun/papers/old/thrun.pf-in-robotics-uai02.html). Подтверждает применимость многогипотезного фильтра; сама применимость метода не доказывает калибровку конкретных полигонов проекта.
